# Evidence Record Schema

The frozen files in `records/` use:

```text
schema: trialdiff.alpha_demo_record
demo_version: v0.1-alpha
```

Each record is a self-contained export wrapper around the canonical TrialDiff Evidence Record generated by the Python pipeline.

## Top-Level Fields

- `schema` - exported record schema identifier.
- `demo_version` - frozen demo version.
- `event_id` - deterministic Evidence Record ID.
- `study` - trial metadata needed for inspection.
- `versions` - from/to ClinicalTrials.gov version references and submitted date.
- `classification` - deterministic classification output.
- `changed_paths` - JSON Pointer paths changed by the patch.
- `patch` - JSON Patch operations.
- `claims_supported` - claims supported by the source data and deterministic rules.
- `claims_not_supported` - explicit non-claims.
- `review_question` - neutral question a reviewer should ask.
- `provenance` - hashes and source fields.
- `live_urls` - deployed Evidence Record, canonical JSON, and trial pages.
- `citation_text` - short citation string.
- `source_corpus` - alpha corpus and selection metadata.
- `canonical_evidence_record` - the canonical generated Evidence Record payload.

## Stable ID Rule

Evidence IDs are deterministic over:

- NCT ID;
- from/to version;
- patch hash;
- headline category;
- sorted changed paths;
- rule-set hash;
- evidence version.

Changing the source patch, rule set, headline category, or evidence template version changes the generated ID.
